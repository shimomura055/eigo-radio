# Q1〜Q3 ユーザー提示文案(Fable向け、2026-10-14、KP-GLOSS-ALIGNMENT-PRODUCTION-01 委任_01)

前提: 「最終英語KPと日本語glossの意味的整合は基本品質要件」(ユーザー2026-10-14)。承認済みPrompt・Rule7・Gate・A'は変更していません。この段は新しい処理フロー1段+新しい課題指示文を含むため、Production採用はユーザー判断です。

## 何が起きていたか(平易)
日本語の意味(gloss)は、英語KPが最終確定する「前」の候補フレーズに対して作られます。その後KPが長く確定すると(例: `based on` → `based on interviews`)、日本語は「～をもとにした」のまま残り、音声でも「なになにをもとにした」と読まれて意味が合いません。これを直す追加の1段が「gloss再整合」です。

## Q1: gloss再整合段を正式仕様として採用しますか
- 内容: KPが候補より伸びたitemだけ(対象0件ならAPI呼出なし)、同じモデル(gpt-6-luna)で日本語glossを最終KP基準で作り直す。承認済みgloss規則は選定Promptから実行時に抽出して流用。「KPにsomething/someone/one's等が無いのに『～』が残る」は機械的にFAIL。
- 効果(実測): 不整合だった対象 6/8 → 再整合後 0/16(目視+決定論)。整合済みのitemは無変更。
- 費用(実測ベース): 通常 約JPY0.014〜0.08 / 記事セット、最悪 約0.57、絶対最悪(外側retry込) 約1.7。70円上限に対し通常は0.1%未満。
- 限界: 検証標本は小さい(ユニーク対象8件)。1,000本あたりの不整合は、再整合なしで約45〜105 item、再整合ありは実測0(統計上の上限は最大約11〜27 item)。
- 課題指示文(新規Prompt)全文: 下記。承認をお願いします。

```
### 課題指示文 全文(user、固定部。【】の対象項目/記事本文は実行時に差し込み)
```

## Q2: 再整合に2回失敗したときの扱い
- (ii)[既定・推奨] 最終KPを維持し、`gloss_alignment_status=FAILED`としてrun summary・NOTICEファイル・標準出力へ必ず通知する。Human Reviewへは自動送りしない。KPを短くして意味を損なうリスクが無い。glossは旧のまま(不整合の可能性)が残る=通知で人が気づく。
- (i) 条件付きでKPを候補へ戻す(戻し先が末尾機能語で終わらず原文内に連続して存在しRule7を通る場合のみ。それ以外は(ii))。意味は整合するが、canonicalizationの判断(補語復元等)を捨てる。
- 切替はconfig 1行(`GLOSS_ALIGNMENT_FALLBACK_MODE`)。

## Q3: 承認が出るまでの扱い
- この段は既にProduction経路に配線済み・flag既定ON。承認前の運用案: (a)[推奨] run起動側で`EIGO_KP_GLOSS_ALIGNMENT=0`を指定し、承認まで新規量産runで通さない(既存Coffee完成物は成立済み・撤回しない)。(b) ONのまま量産し、FAILED通知を必ず確認する。(c) 承認まで新規量産runを止める。
