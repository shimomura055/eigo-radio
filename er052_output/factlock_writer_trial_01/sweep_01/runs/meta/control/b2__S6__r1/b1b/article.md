# Humans Handled Muse’s Phone Test. Meta Rolls Back the Feature

Was it AI or a person making the call? In a test involving some calls through Muse, trained human contract workers—not AI—made the calls and completed the conversations with the other person. The workers were responsible not only for making the calls, but also for carrying the conversations through to the end. However, this was a test involving only some calls through Muse, not all of them.

The test raised privacy concerns. Meta employees worried that when human contract workers handled the calls, sensitive user information needed to complete the conversations might be shared unintentionally with call-center contract workers. The concern was that user information might be shared unexpectedly because a person was handling the call. There is an important distinction here. What was raised was a concern about information being shared, not that a large-scale data leak had actually happened. We should not mistake concern about a possibility for an actual large-scale data leak.

The vice president of Meta’s Superintelligence Labs admitted that starting a test in which contract workers made calls without proper disclosure was a “mistake.” In other words, what was acknowledged as a problem was starting the test in which people handled the calls without proper disclosure. Meta then rolled back the human concierge feature for the time being. What was rolled back here was the human concierge feature. Meta did not shut down all of Muse. Rolling back the feature that lets people make calls and shutting down all of Muse are not the same thing.

## In one line
Meta rolled back Muse’s human concierge feature after contractors, rather than AI, handled some calls.
