# EVAL_PROMPT_01: 評価LLM用プロンプトと呼び出し条件(委任_01、設計のみ・API実行なし)

凡例: 【確認】=一次資料/repo実物で確認 / 【見積】=計算上の見込み / 【推測】=未確認の推し量。

## 1. 設計方針
- 1回の呼び出しで1ケースだけを評価する(複数ケースを1プロンプトに入れない)。ケース間の汚染(直前ケースの判定に引きずられる)を避けるため。トークンは増えるが、10ケースで見積は小さい(MODEL_OPTIONS_COST_01.md)。
- 渡す情報は `eval_items_01.json` の5項目(case_id, fact, target_sentence, context_before, context_after)のみ。人間判定、Checker判定、旧/新Writer、Rewrite有無、テーマ名、fact_id、出典pathは渡さない。台帳の `notes_for_writer`(「サービス全体を停止したとは書かない」等のヒント)も渡さない(ヒントで判定が変わるのを避ける。ただし、これは本番Checkerが見る情報との差でもあり、PREREGISTRATION_01の限界欄に記載)。
- 本文は `eval_prompt_01.txt`(プロンプト原文、runnerが読み込む正本)。3分類の定義はユーザー指示の「重大は主体・対象の入替／肯定否定・方向の反転／数量・時系列の重大変更／台帳と逆の意味に限定」を固定した。
- 定義文の語句そのものが結果を左右する変数である。とくに「不在・非公開の断定はそれだけではBにする。ただし台帳と矛盾する内容を読者に信じさせるならC」の1文は、K02(jb9k型)がCになるかBになるかを分ける境界であり、答えを漏らさずに4種類の限定と整合する書き方にした【推測: この文言でK02を拾えるかは実行するまで不明】。

## 2. 出力形式(JSON固定)
`{"case_id", "label"∈{A,B,C}, "reason"(日本語60字以内), "misread_type"∈{主体対象入替, 肯定否定方向反転, 数量時系列変更, 台帳と逆, なし, その他}}`
- runner側で検証する: JSONとしてparse可能 / case_idが入力と一致 / labelがA,B,C / misread_typeが列挙値 / reasonが60字以内(超過は警告のみで採否に影響させない) / A⇔"なし"の整合。違反は1回だけ再呼び出しし、元の応答も保存する(RUN_PLAN_01.md)。

## 3. 呼び出しパラメータ(固定、再現性のため)
| 項目 | 固定値 | 備考 |
|---|---|---|
| system/developer | `eval_prompt_01.txt` 全文 | 全モデル同一 |
| user | `eval_items_01.json` の1要素をJSON文字列化 | キー順固定 |
| temperature | 0(対応するモデルのみ) | 【未確認】gpt-6系など推論モデルがtemperature指定を受け付けるかは、実行前の¥0確認(API仕様書の確認、またはRUN_PLAN手順0)で確定する。非対応なら指定せず、「指定なし」をログに残す |
| seed | 固定値 20261009(対応するAPIのみ) | 非対応なら省略しログに記録 |
| 推論量(reasoning effort) | 各モデルの既定ではなく明示固定(medium相当) | 【未確認】パラメータ名・可否はモデルごとに確認 |
| 出力上限 | 余裕を持たせる(推論トークン込みで6,000程度) | DeepSeekは推論トークンが可視出力と同一予算を消費する【確認: ER-005-RESEARCH-MODEL-AB-01_report.md L113】ため、小さい上限だと空応答になる |
| ケース提示順 | `eval_items_01.json` の並び(固定seed 20261010でシャッフル済み)。全モデル・全repで同一 | 順序はprompt内容に影響しない(1ケース1呼び出し)が、ログ順を揃える |
| 繰り返し | rep1,rep2(同一条件で2回)。best-of・再実行による選択は禁止 | 自己一致の測定用。費用はMODEL_OPTIONS_COST_01.md |

## 4. ケース構成(盲検性の確認)
- `eval_items_01.json` は10件、case_idは固定seed 20261009でランダム生成の6文字英数字。
- 盲検の限界【確認】: 対象文そのものの内容(Meta、Hormuz等の固有名詞)から、人間が見ればテーマは分かる。評価LLMにとってテーマ名は判定に不要だが除去はしない(文の意味を壊すため)。旧/新Writer、人間判定、Checker判定に結びつく情報はファイル内に含まれない。
