# 方式A v1: 既存4軸 × 1〜5点

目的: 既存4軸(PASS/FAIL)を5段階化して識別力が出るかを見る。軸数は増やさない。
driverは下の2セクション(DEVELOPER_ADDENDUM / USER_CRITERIA)だけを読み込む。他の見出しは解説でありPromptに入らない。

## DEVELOPER_ADDENDUM
評価は4項目(A〜D)それぞれ1〜5の整数で採点する。5=非常に優れる、4=優れる、3=標準的、2=弱い、1=ほぼ満たさない。
本文が示す通りに採点し、全項目に差を付ける必要も、高得点・低得点を避ける必要もない。満点も最低点も本文が示すなら付けてよい。
各項目に本文からの根拠引用(1〜2個)と日本語の理由(2〜3文)を付ける。overallは4項目を踏まえた総合1〜5点(平均の機械的な丸めでなくてよい)。

## USER_CRITERIA
[方式A: 既存4軸を各1〜5点で採点]
A. 中心事件・変化: 追える中心事件・行動・関係変化・選択があるか。
   5=中心事件が明確で、人物の選択・関係・状況が目に見えて変わる / 3=事件はあるが変化が小さいか曖昧 / 1=事件・変化がほぼ追えない。
B. 読者の関心: 読者を引っ張る要素(Hook・緊張・意外性・疑問・人間関係・共感・皮肉・強い状況設定)があるか。派手なHookは必須ではない。
   5=冒頭から終盤まで読み続けたくなる要素が複数ある / 3=要素はあるが弱いか一部のみ / 1=読者を引っ張る要素がほぼない。
C. 展開・余韻: 意味のある展開・変化または余韻が残るか。明確なオチは必須ではない。
   5=展開が効いていて、読後に強い余韻や解釈が残る / 3=展開か余韻のどちらかは残る / 1=展開も余韻もほぼない。
D. 短編化適性: 英語の短編(280〜420語、A2〜B1向け)へ圧縮しても作品の魅力が残るか。文体・長い描写・心理描写そのものが魅力の中心で削ると消える作品は低い。
   5=圧縮しても魅力の核がほぼ残る / 3=核は残るが重要な要素が一部失われる / 1=圧縮すると作品の魅力がほぼ失われる。

[手順]
1. key_facts に中心事件・主要人物・転換点・結末を書く(自分の言葉でよい)。
2. A〜Dを採点する(score, evidence_quotes, reason)。
3. overall(score, comment)を書く。
4. 出力はJSONのみ。
