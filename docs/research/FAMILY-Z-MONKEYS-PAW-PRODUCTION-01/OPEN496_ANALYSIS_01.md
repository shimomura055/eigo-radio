# OPEN496_ANALYSIS_01 (OPEN-496: Adv会話の極短clipで速度v2の長さ比Gateが停止、FAMILY-Z-MONKEYS-PAW-PRODUCTION-01 委任_03、2026-10-24)

分類=**ユーザー判断要**(Gateの条件変更=品質ライン変更にあたるため。実装はしていない)。API 0(分析のみ)。分析script=調査用の一時script(repoには置かない)、集計元=`er026_output/**/narration/*_original.wav` と `.wav` のペア全数(`wave`モジュールで実測)。

## 1. 事象と原因(実測で再現)
- 事象: 『猿の手』Adv `full_story_part3_c5`(`"Wait!"`、原音0.771秒)が `verify_z_speed_profile`(`er063_family_z_audio_01.py:1589`、`ADV_DIALOGUE_RATIO_MIN/MAX = 0.93, 0.96` = L60)で wav/original長さ比=0.9670 となり FamilyZSlowdownGateStop。他の会話16clipは全て範囲内。
- 原因: atempo=1.06(`er008_a2_postprocess_slowdown_01.py:apply_a2_slowdown`、WSOLA系)の出力は理論値(原音/1.06)より **約10〜19ms長い**(固定オーダーの誤差)。長さ比 = 1/1.06 + 誤差/原音長 なので、原音が短いほど誤差の比への寄与が大きい(理論値0.9434)。0.771秒では 0.9434 + 0.0182/0.771 = 0.9670。
- **ffmpegでの再現**(API 0、`apply_a2_slowdown`と同一のコマンド `atempo=1.060000 -ar 24000 -ac 1 -sample_fmt s16`、再生成前の原音のバックアップで実施): 原音0.7710秒 -> 出力0.7455秒、比0.9670、誤差18.2ms(runの記録値と完全一致)。同じ原音の頭に無音を足して長さだけ変えると比が下がる: 長さ0.971秒=0.9599(誤差16.0ms)、1.271秒=0.9522(11.2ms)、1.771秒=0.9470(6.4ms)。=原因は『長さが短いこと』による比の感度で、音声内容の異常ではない。

## 2. 影響範囲(過去run全数)
- **Gate自体がFamily Z限定**: `verify_z_speed_profile`はZの`run_audio_gate`からのみ呼ばれる(docstring「Xには影響しない」、grep: `ADV_DIALOGUE_RATIO`は`er063_family_z_audio_01.py`とそのtestのみ)。委任文の『X/Z共通Gate』は実際にはZのみ(Xの会話clipは本Gateの対象外)。Std会話は減速なし(比≈1)で本問題の対象外。
- 対象=Adv会話clipの(原音, 処理後)ペア: 現存する全数124件(Z 5作品: 『二十年後』『メロス』『賢者の贈り物』『開いた窓』『猿の手』のrun。『開いた窓』の保存copy[preserve]重複を含み、重複を除くと一意90組。『猿の手』c5は再生成後の新テイク1.051秒を含み、失敗した旧テイク0.771秒は含まない)。
- 原音長さ別(比の範囲0.93〜0.96):
| 原音長さ | 件数 | 比のmin〜max | 範囲外 |
|---|---|---|---|
| <1.0秒 | 1 | 0.9588 | 0 |
| 1.0〜1.2秒 | 1 | 0.9535 | 0 |
| 1.2〜1.5秒 | 4 | 0.9460〜0.9551 | 0 |
| 1.5〜2.0秒 | 27 | 0.9449〜0.9531 | 0 |
| 2.0〜3.0秒 | 38 | 0.9359〜0.9518 | 0 |

- **長さ<1.0秒の件数=現存124件中1件(『猿の手』`full_story_part1_c9` 0.961秒、比0.9588=範囲内ぎりぎり)。失敗した旧テイク0.771秒を加えた125件では2件(1.6%)、範囲外は旧テイクの1件(0.8%)のみ。**
- 誤差(出力長 - 原音/1.06)の分布(124件): 平均11.0ms、標準偏差5.9ms、最大18.8ms、最小-19.5ms(長さによらずほぼ一定の10〜19msが上乗せされる傾向)。比が0.96を超える条件 = 誤差/原音長 > 0.0166。誤差が最大級(18〜19ms)なら原音が約1.1秒未満で、平均級(11ms)なら約0.66秒未満で範囲外になる。
- 再現頻度の見積: 極短clip(<1.1秒)の発生率が約1.6〜2.4%/clip、Z作品1本のAdv会話clipは約10〜19件のため、**作品1本あたり約15〜35%の確率で1件前後が極短clipになる**(誤差が最大級になる場合のみ範囲外=実際に停止する確率はその一部。0.771秒の本件のように『Wait!』『No.』等の1語感嘆文が主因)。ホラー/会話劇ほど発生しやすい。

## 3. 対策案とQCD影響
- **案A: 極短clipは『絶対誤差』許容を併用する**(原音長さ<1.5秒のclipに限り、比が範囲外でも `|出力長 - 原音/1.06| <= 25ms` ならPASSとする)。25msの根拠=過去124件の最大18.8msに余裕を持たせた値。効果=本件(18.2ms)はPASS、真の未処理(誤差が原音の6%=0.77秒で46ms)や誤適用は引き続き検知できる(上限25msは0.77秒の3%、実効tempoは約1.034〜1.06の範囲)。
  - Q: 本件の実効高速化は+3.4%(目標+6%)だが、25msは音節の1/10程度で聴感上の差は事実上ない(聴感の最終判断はユーザー)。Gateは『未処理/誤処理の検出』が目的であり、極短clipの固定誤差を除けば検出力は変わらない。
  - D: 以後、極短clipで停止しない(Gate停止+Fable判断+再生成+再起動の約25〜30分が不要)。
  - C: 追加費用0。
  - リスク: Gate条件変更=承認済み品質ライン(L60)の変更なのでユーザー承認が必要。実装はZのGate1関数のみ(testの追加は小)。
- **案B: 現状維持(極短clipは再生成で対処)**: Gate変更なし、停止したら該当clipのみ再生成(今回=約0.17円、1 TTS call)。
  - Q: 品質ラインは不変。ただし極短clipは再生成しても毎回同じ誤差(10〜19ms)が乗るため、再生成が通るかはTTS生成のたびの原音長のゆらぎ次第(今回は0.771秒->1.051秒になり比0.9535でPASS。ただし『Wait!』の長さが約0.3秒変動した偶然に依存する)。
  - D: 停止のたびにFable判断・1起動が必要(約25〜30分/回)。上限なし(確率的)。
  - C: 再生成0.17円/回で費用はほぼゼロ。
- **案C: 比の計算で固定オフセットを補正する**(比 = `(出力長 - 11ms) / 原音長`)。範囲0.93〜0.96は据え置き。
  - Q: 本件は(0.7455-0.011)/0.771=0.9527でPASS。ただし補正値11msは統計的な平均(σ5.9ms)で、ffmpeg/WSOLAの内部動作に依存する経験値であり、将来のffmpeg更新やclip内容による誤差変動に弱い(誤差最大級の18〜19msでも短いclipは範囲外になりうる)。
  - D: 案Aと同等。C: 0。
  - リスク: 案Aより根拠が弱い(経験的な平均値への依存)。

## 4. 推奨(Fable推奨の材料)
**推奨=案A**(根拠: 誤差10〜19msが長さに依らず一定であり、長さ比は短いclipほど構造的に不利になる=Gateの『比』基準の設計上の盲点。絶対誤差25msは過去最大18.8msを内包し、検出対象の真の異常[未処理: 約6%=0.77秒で46ms、誤適用]はその1.8倍以上で区別できる)。案Bは今回のようにたまたま通るまで再生成が必要で確率的、案Cは経験値依存。実装は`verify_z_speed_profile`のAdv分岐1箇所と`er063_family_z_speed_v2_test_01.py`の追加のみ(見積: 0.5時間、API 0)。ユーザーが現状維持(案B)を選ぶ場合は、停止のたびに該当clipのみ再生成でよく、品質ラインは不変。
