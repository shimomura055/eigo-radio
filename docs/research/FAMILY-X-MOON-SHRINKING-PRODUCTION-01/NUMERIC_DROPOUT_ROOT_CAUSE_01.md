# NUMERIC_DROPOUT_ROOT_CAUSE_01 (FAMILY-X-MOON-SHRINKING-PRODUCTION-01 委任_03、2026-10-25)

結論: 数値脱落は「Writer(W-1 R0)が【中核数値】を使わない選択をすること」自体が原因で、現行の承認済み仕様はWriterに中核数値の本文記載を課していない(許可のみ・必須化なし・出力検査なし)。run_ms_01(記号QA再生成あり)だけでなく、同一入力でW-1以降だけを再実行したrun_ms_02(記号QA再生成なし)でも再現した。よって「記号QA再生成が原因」仮説は反証され、既存不具合(仕様と実装の矛盾)ではなく**仕様の空白(必須化規則の不在)**である。

run_ms_01のLedger・B3・注記・丸めoverlay(sha一致=`5c3690d8e65027dce0...`)をそのまま再利用し、W-1以降のみを正式経路(runner `--stage all`、既存B3/Ledger再利用)で再実行。Prompt改変なし。結果: 記号QA再生成なし(`run_ms_02/ja_writer/runtime_evidence.json` symbol_qa.r0.regenerated=false)にもかかわらず、R0に使われた数値は「8,900本超」のみ(概数可とされた唯一の中核数値)。約42〜46m・約4億年・11cm/百万年・750m〜1.1kmはまたも脱落。R2・Advanced・Standardも同様。

## 3. 仕様上の根拠
- Writerの数字規則5(`er053_family_x_factlock_ja_writer_01.py:87-94`): 「【中核数値】と印の付いた数字**だけを、記事で使えます**」。使用は許可であり、必須記載の規則は無い。使う場合は表記のまま・本文の文にタグ必須。
- R0 Promptの別ブロック(AN3の第2文のみ残置)・DEVELOPER_MESSAGE(`er019_family_x_ja_writer_o_r1_r2_01.py:66`)に数値保持の指示は無い。AN3の第1文「数字・時刻は基本的に使わない」はRule 5で置換済み(`er053_family_x_factlock_ja_writer_01.py:135-145`、CURRENT_SPEC:915)だが、R1/R2の指示は「事実関係は変えずにもっとエンターテインメント性を高く」(`:71-72`逐語)のみで数値保持規定なし。
- 検査: 中核数値が記事に残ったかを確認するGate・契約検証(V1〜V10)は無い(B3注記の契約検証は注記の整合を見るのみ。CURRENT_SPEC:2877-2889『中核数値丸め』の節も「概数表記の指定」に限定され、必須記載を扱わない)。
- B3の【中核数値】は「Writerが使ってよい数字の許可リスト」であり、「使うべき数字」ではない。
