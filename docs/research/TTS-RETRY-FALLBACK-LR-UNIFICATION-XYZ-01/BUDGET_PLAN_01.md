## 4. 量産原価への影響(目標70円/記事セット。Charter 3)

**結論(所見・推定)**: 量産単価への影響は**ほぼ0〜+1円/セット**。根拠:
1. **回数が増えるのは「LRが発動した後」だけ**: LRなし部位(日本語・KP・KP解説・Zセリフ)は最大回数も1ブロック3回(KPは4回)で変わらず、待機が増えるだけで**費用は増えない**。Adv英語の③は「3回目の同じ1 attempt」のStyleが変わるだけで試行回数は同じ。
2. **LRあり部位の増分**: LR後の再生成が「1回」から「最大3回」になる。①'がPASSなら旧と同じ1回(増分0)。増分はLR発動(③NG、実績で全clipの約1〜2%: Z dialogue「3回以上」6/347=1.7%、JA comment 7/102=6.9%[LRなし])かつ①'NGの場合の最大+2 attempt。1 clipあたり期待増分≒`P(③NG)×P(①'NG)×2×単価`≒0.02×0.3×2×1.0≒0.01円、100 clip/記事で≒**+1円未満**。
3. **Z topic_intro_en(U-06)**: 冒頭英語は短文・再試行実績0(34 entry)で、LR有効化の費用影響は無視できる。
4. **U-03(QA単独NG)**: 旧=cooldown+3 TTS後にLR不発→HR。新=同じ3 TTS(省略しない)で費用同額。LR LLM呼出は旧同様に0。HR後の再生成連鎖(OPEN-533)は別件。
5. **LR Luna呼出**: LR発動1回あたり約0.6〜1.0円。発動頻度が1〜2%なら記事あたり約0.1〜0.3円。
上の頻度は棚卸し時点の実績値であり、委任_03のevidenceでは**頻度ではなく1イベントあたりの実費**(case別の`cost_jpy`)を測る。記事あたりの総額は`attempts_log`のoffline集計(API 0)で再計算して報告する(本evidenceの強制NG費用は量産単価に含めない)。

## 5. 制作時間への影響

- **待機**: ブロックあたり600秒→180秒で**−420秒/イベント**。LRありで最大2ブロック=360秒(旧: 600秒+LR後1回で実質>600秒)。日本語・KP・KP解説・Z legacyは新たに**+180秒/イベント**(3回目に到達した場合のみ。実績: JA comment 3回以上 7/102=6.9%)。
- **記事あたりの試算(推定)**: 英語のcooldown発生を記事あたり3〜6イベント、日本語等の新規待機を0.5〜1イベントと仮定すると、旧 約30〜60分 → 新 約9〜18分+0.5〜3分。**差分≒−20〜−40分/記事**(直列。chunkが多く失敗が集中すると線形に増えるが、1 chunkの最大待機は360秒で旧より短い)。
- **evidenceの所要**: 実180秒待機を含むため、case別のwall time=待機×180秒+TTS/ASR(約20秒/attempt)+LR(約30秒)。6 process並列で**最長process=3110秒(約51分)**、直列なら11890秒(約3.0時間)。並列化により約3.8倍短縮。
- 実装(委任_02)の工程見込みは §7。
