# 人間確認の優先順位付け v1(O2、OPEN-233-CHECKER-ACTION-POLICY-DESIGN-01)

位置づけ: 設計案(未承認、Trial限定)。新しい抽出callは作らない。**既に支払い済みの不一致信号**だけを使い、検出層ではなく「人間確認パックの順位付け」に限る。重大度は機械的に決めない(型→重大度にしない)。

## 1. 使う信号(すべて既払い・決定論で取得)
| 信号 | 取得元 | 備考 |
|---|---|---|
| S-A: 2nd opinion不一致 | Stage2の1回目と2回目(O1: 文を見ない判定)でmateriality/belief_vs_ledgerが不一致 | 2-of-2の既存出力 |
| S-B: belief_vs_ledger不一致 | 同一claimの複数call(1回目/2回目、cycle間)で値が異なる、または`unclear` | ②の出力 |
| S-C: リンク不一致 | Stage1 r3の`support_fact_ids`とWriter注釈(④)のfactが食い違う | ④導入(段階3以降)までは使わない |
| T: ガード対象型 | 決定論規則(否定・不在/全称/因果/主体新規/数値。限定語消失は段階2持ち越し) | 重み付けにだけ使う |
| V: Stage2最終判定 | contradicts / unclear / unsupported_new_claim / consistent | 既存出力 |

## 2. スコア規則(初期値。調整は段階2のdevのみ)
各候補(文)の整数スコア(合計):
- ガード対象型T該当: +1
- V=contradicts: +4、unclear: +3、unsupported_new_claim: +2、consistent: 0
- S-A成立: +2、S-B成立: +2、S-C成立: +2(段階3以降)
- QUALITY/ACCEPTABLEへ格下げが成立し、かつS-A/S-B/S-Cのいずれかが成立: +1(格下げされたまま通る不確実な文を優先)
- 記事単位スコア = その記事の候補の**最大スコア**(同点は候補数が多い記事を優先)。
- スコアは**確認の順位**であり重大の判定ではない。人間が判断する。

## 3. 運用: 上位10%を人間確認パックへ
1. 対象: 同一バッチ(Trial/段階2評価の記事集合)を記事単位スコアの降順に並べる。
2. 上位**10%**(切り上げ、最低1記事)を人間確認パックへ入れる。10%を超えて入れない(人間レビュー率の上限と整合)。
3. パックには、該当文・reader_belief・contradicting_fact_ids・Ledgerの該当fact・使った信号を並べる。**Checker側の重大度判定は伏せ**、人間が独立に重大度を付ける。
4. 同点で10%境界を跨ぐ場合は、V=contradicts/unclearを含む記事を先に入れる。それでも決まらなければ記事IDの辞書順(恣意性の排除)。
5. 人間確認の結果は順位付け精度(上位10%内の重大捕捉率)の評価に使う。副指標であり、段階2の合否ラインには含めない。

## 4. 制約・限界
- 信号はLLM出力の不一致で、**両callが同じ誤りをする場合は立たない**(O1でも完全には解消しない)。捕まえる保証ではない。
- 段階2のdevで、上位10%に重大が何件入るかを報告する(件数が少なく有意差は言わない)。held-outは1回のみ(事前登録に従う)。
- Production採用なし。人間レビュー率の上限(≤10%)との整合は、構造要素由来STOP(≤3%)と合算して段階2で実測する。
