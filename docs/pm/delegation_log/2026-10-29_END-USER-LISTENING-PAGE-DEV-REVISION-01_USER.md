# Claude Codeへの指示案｜End User向け記事視聴ページ DEV改修

## 1. 目的・作業範囲

End User向け記事視聴ページのDEV試作について、ユーザーが指定したデザイン・表示内容・再生操作を修正する。

目的は、英語音声を聞きながら本文を読み、単語の意味や詳しい解説、日本語訳を自然に確認できる、使いやすい記事ページにすること。

対象：
https://shimomura055.github.io/eigo-radio/user_test/dev_enduser_page_01/index.html

**今回はDEV試作の修正のみ。Production採用・Production Wiringは行わない。**

### 最重要：ChatGPTによる修正は全面破棄

前回ChatGPTが実施した改修は、ユーザーによって全面不採用となった。

- Git履歴を確認し、ChatGPTが変更したHTML／CSS／JavaScript／JSON等を特定する。
- Claudeが当初完成させたPhase 1・2のDEV試作版を復元し、そこから改めて修正する。
- ChatGPTが作成した実装や日本語訳を、そのまま採用しない。
- 既存の正式Production、公開記事、音声、他タスクの変更は巻き戻さない。
- 元のDEV試作が持っていた1文ハイライト、文クリック再生、再生バー、シーク等の機能は維持する。

## 2. 修正指示

### ① 全体再生ボタンの配置・サイズ

現在の「全体を再生」ボタンを、**Standard／Advanced切り替えタブの下**に移動する。

- 現在より大きく、押しやすくする。
- 全体再生の主要操作として視認しやすいデザインにする。
- Standard／Advanced切り替え機能自体は変更しない。
- PC・スマートフォンの両方で配置を確認する。

### ② Key Phraseの発音

Key Phrase・Wordの音声ボタンは、**英語音声のみ**を再生する。

- 日本語の意味の読み上げは不要。
- 既存音声を確認し、英語部分だけを再生する。
- 必要な場合はDEV側で再生方法を調整する。
- 正式Productionの音声や生成仕様は変更しない。

### ③ 本文下の単語・表現の意味一覧

Full Storyの各Partの本文直下に、英語表現と日本語の意味をまとめて表示する。

対象は以下をすべて含む。

- 本文中で意味を表示する対象となっている単語・表現
- Key Phrase・Wordに選定された表現
- Vocabulary & Expressionsで詳しく解説される表現

ただし、該当Partの本文に登場する表現を対象とし、同一表現を重複掲載しない。

**この一覧では、簡潔な日本語の意味だけを表示する。**

長い解説は掲載しない。意味は本文の文脈に合わせる。

#### 詳細解説へのリンク

Key Phrase・WordまたはVocabulary & Expressionsで詳しい解説がある表現には、解説があると分かるリンクを設ける。

リンクをクリックすると、**該当する表現の解説位置**へ移動する。

単にコーナーの先頭へ移動するだけでは不可。

### ④ 意味一覧のデザイン

本文下の意味一覧は、縦方向に長くなりすぎないようにする。

- PCでは左右2列。
- 控えめな背景色と枠で囲む。
- 本文より目立たないデザインとする。
- 日本語意味は読みやすい濃さを確保する。
- スマートフォンでは可読性を優先し、適切に列数・文字サイズを調整する。

### ⑤ Comment／Partごとの日本語訳

英語原稿に対応する日本語訳を追加する。

対象：

- Comment 1〜4
- Full Story Part 1〜3
- In One Line

**それぞれの英語本文の直後に日本語訳を表示する。**

添付済みの参考スクリーンショットの構成を参考にすること。

- 英語本文と日本語訳の対応が明確に分かるようにする。
- 既存の承認済み日本語原稿・翻訳データがある場合は優先的に再利用する。
- 既存訳がない場合は、原文の意味・事実関係を保持して作成する。
- ダミー文や空欄を残さない。
- 英語本文・既存音声は変更しない。

### ⑥ 再生ボタンの一本化

各パートに存在する以下の2つのボタンを整理する。

現状：
- 「▶ このパート」
- 「通しで ▶」

変更後：

**「▶ ここから再生」**

ボタンは1つだけ表示する。

期待動作：
- 指定したパートの開始位置から全体音声の再生を開始する。
- パートが終了しても、続きの音声を途切れず再生する。
- 「このパート」ボタンは完全に削除する。
- Key Phraseの発音ボタンは別機能として維持する。
- 固定再生バー、シーク、文クリック再生を壊さない。

### ⑦ Full StoryとIn One Lineの連結

現在はFull StoryとIn One Lineが別のカードに分かれている。

これを一つの連続したまとまりに変更する。

- Full StoryのComment 4の後にIn One Lineを配置する。
- In One Lineの見出しは維持する。
- 不要なカードの境界や大きな余白をなくす。
- 再生・文ハイライト・日本語訳が正常に機能すること。

### ⑧ 文法解説のある記事での表示確認

AI島に加え、文法解説が存在する『月は少しずつ縮んでいる？』Advancedを使って確認する。

- Vocabulary & Expressionsが正常に表示される。
- Grammar & Sentence Structureも正常に表示される。
- 両コーナーが自然なレイアウトで閲覧できる。
- 文法解説0件ではコーナー全体を非表示とする。
- 既存の実データを使用し、ダミー解説を作らない。

今回の確認のために文法の生成・選定仕様を変更しない。

### ⑨ 単語・フレーズ解説の文字サイズ・色

**現状は文字が小さいため、もう少し大きくする。**

対象はVocabulary & Expressionsの解説部分。

- 英語・日本語とも読みやすい文字サイズに拡大。
- 日本語の意味が薄いグレーで読みにくいため、英語と同じ黒系の濃い文字にする。
- 見出し・意味・本文解説の視覚的なバランスを整える。
- PC・スマートフォン双方で確認する。

### ⑩ 本文下線の説明文を削除

以下の凡例を削除する。

「本文の下線：太字＋二重下線＝重要表現／太字＋下線＝追加の解説つき表現／下線のみ＝意味を下の一覧で確認」

**説明文のみを削除し、本文内の太字・下線などの強調表示自体は維持する。**

## 3. 検証方法・自己確認

今回の改修では、**コードを変更しただけで完了と報告することを禁止する。**

10項目それぞれについて、以下を実施する。

1. 元のDEV試作を復元する。
2. 修正対象の既存コード・表示データ・音声構成を確認する。
3. 各項目を修正する。
4. ローカルブラウザで表示・操作を検証する。
5. PC・スマートフォン幅でレイアウトを検証する。
6. GitHub Pagesに反映する。
7. **公開URLを実際に開き、反映された画面で同じ項目を再検証する。**
8. 不具合があれば原因究明→修正→再検証を自律的に繰り返す。

特に以下は実操作で検証する。

- 全体再生ボタンがタブの下に配置され、サイズが拡大されている。
- 「ここから再生」を押すと、後続パートまで連続再生される。
- Key Phrase発音は英語のみが聞こえる。
- 本文下の意味一覧が2列で表示される。
- Key Phrase・Word、Vocabulary対象表現が意味一覧に反映されている。
- 解説リンクが該当表現に直接移動する。
- Comment・Part・In One Lineの日本語訳が欠落なく表示される。
- Full StoryとIn One Lineが連続して表示される。
- 文法解説あり／なしの双方が正常に表示される。
- 解説文字サイズ・色が変更されている。
- 下線凡例が削除され、本文の強調表示は残っている。
- 1文ハイライト、レベル切替、シーク等の既存機能にRegressionがない。

公開ページでは、キャッシュやデプロイ未反映によって旧版を誤認しないようにする。

構文検査・単体テストだけではPASSとしない。

## 4. QCD・作業境界

優先順位：**Q ＞ D ＞ C ≫ 開発費用**

- 承認済みの本文・音声・学習品質は維持する。
- DEV試作以外のProductionを変更しない。
- 不要な音声再生成やAPI利用を避ける。
- 既存データを再利用する。
- 独立作業は並列化し、不要な待機・日付分割をしない。
- 技術的不具合は承認範囲内で自律的に解決する。

重大な品質・安全問題、予算超過、未承認仕様への変更が必要な場合はSTOPし、ユーザーへ報告する。

今回の修正版はDEV試作であり、Production採用の判断はユーザーが別途行う。
