# Claude Code指示｜Family Z「告げ口心臓」学習項目再選定・音声再制作・完成版公開

## 1. 目的・基本方針

Family Z「告げ口心臓」（The Tell-Tale Heart）について、既存のStandard／Advancedスクリプトを変更せず、学習項目の選定から音声制作・完成版公開までを現行Production仕様で実施してください。

**ユーザー承認済みの制作範囲：**
- Standard／Advancedの既存スクリプトをそのまま再利用する。
- Key Phrase・Key Word・文法を現行V3方式で再選定する。
- ユーザー確定後、学習解説・音声を制作し直す。
- 本文音声も現行Production仕様で再制作する。
- ①②③の本文ハイライトを含む完成版を構築する。
- Standard／Advanced両方の最終試聴ページを提出する。

**Status：制作作業承認済み。学習項目の新しい選定結果は未確定。**

今回の制作承認は、未選定の学習項目をAIが独断で確定する許可ではありません。

## 2. 既存成果の確認と固定

最初に、Repo・ローカル成果物・CURRENT_SPEC・DECISION_LOG・OPEN_ITEMSを確認してください。

特に以下を明らかにする。

1. 「告げ口心臓」Standard／Advancedの最新の正式スクリプトの所在・版・ハッシュ。
2. 過去のKP選定結果と、どの工程まで進んでいたか。
3. 過去の音声生成・Chunk版・公開ページ・ユーザー承認の状態。
4. 現行Production仕様との違い。
5. 新方式で再制作する際に再利用できる成果物。

**今回使用する本文は既存のユーザー確認済みスクリプトです。**

R0／R1／R2、英訳、Standard調整等の上流工程は再実行しない。

本文が複数存在する場合は、過去のユーザー承認・最新の正式採用記録を照合して正本を特定すること。正本が特定できない場合は、候補版と差分を提示し、無断で本文を選択・変更しない。

既存成果物は上書き・削除せず、新しいrunで制作する。

## 3. 学習項目の再選定

現行ProductionのV3方式を使用する。

### 候補抽出

- Key Phrase候補：最大7件
- Key Word候補：最大5件
- 候補数を無理に埋めない。
- 各候補に日本語訳とAI選定理由を付与する。
- 本文との一致、語数上限、学習価値、難易度など、既存の承認済み選定仕様を遵守する。

### ユーザー選定区分

| 区分 | 選定上限 | 学習コンテンツ |
|---|---|---|
| ① Key Phrase | 3件 | 詳細な日本語解説＋音声 |
| ② 追加解説 | ①と合わせて5件 | ①と同等の詳細な日本語解説 |
| ③ 本文意味表示 | ①②③合計12件 | 短い日本語訳のみ |

①②の詳細解説は、Standard／Advancedとも日本語で生成する。

①②は解説コーナーで同等の扱いとする。①のみKey Phrase音声を付ける。

### 文法

- AIが候補を順位付けする。
- Top1／Top2のみ提示する。
- ユーザー選定前に学習者向け解説全文を生成する。
- ユーザーは原則1件を選定し、適切なものがなければ0件も可能。
- 2件同時採用は不可。

### フォーム

現行Production Wiring済みのV3フォームを使用する。

Standard／Advancedそれぞれについて、候補・日本語訳・選定理由・文法解説を確認できる状態にし、ユーザーに選定を依頼する。

フォームには候補ID、候補集合ハッシュ、本文ハッシュ等の照合情報を保持する。

**ユーザーによる選定確定まで、後続の確定内容を前提とする制作は進めないこと。**

ただし、選定確定に依存しない本文音声の制作準備や検証は並列して進めてよい。

## 4. 音声の再制作

ユーザーの希望に従い、**本文音声も作り直す。**

現行Family Z Production仕様を使用する。

- 承認済みVoice割当
- Narrator／Dialogueそれぞれの正式音声Style
- 最新のStandard／Advanced速度仕様
- 承認済みChunk分割方式
- 最新のTTS retry／Fallback／Local Rewrite仕様
- Primary／Secondary ASRと承認済み救済方式
- Human Review Lockおよび各品質Gate

今回の音声制作では、旧記事の音声をそのまま完成版として流用しない。

ただし、Voice設定・Style定義・固定Master等、再生成を要しない共通資産は既存仕様に従って再利用し、不要なAPI費用を発生させないこと。

### Local Rewriteに関する注意

現在、別案件でLR後の本文と音声の不一致、およびM3とLRの整合調査が進んでいます。

- 既存Gateを無断で緩和しない。
- LRによって本文と音声が食い違う場合、黙って完成版へ反映しない。
- ユーザー確定済み本文を独断で変更しない。
- 当該調査の結果、正式承認された是正仕様がある場合はそれに従う。
- 未解決問題がある場合は、該当部分のみ適切にSTOPし、独立して進められる作業は継続する。

## 5. 学習解説・記事表示

選定内容確定後、①②③と文法を現行正式仕様で制作・公開する。

**本文ハイライト：**
- ①：太字＋二重下線
- ②：太字＋通常下線
- ③：通常下線のみ

文字色・文字サイズは本文と同じ。背景マーカー・色分けは使用しない。

①②は詳細な日本語解説、③は短い日本語訳のみ。

学習項目の表層形、本文中の出現位置、ユーザー確定日本語訳、候補ID、文法選定結果を保護する。

確定内容を後続工程で再選定・書換えしない。

公開ページには、Standard／Advancedそれぞれの本文・学習内容・音声が一致した状態で反映されること。

## 6. 検証・Production受入条件

- 固定した既存本文と新規制作本文が一致する。
- ユーザー確定済み①②③・文法が正確に反映される。
- 詳細な日本語解説が①②同等の品質・表示形式で提供される。
- ①のみ対応するKey Phrase音声が存在する。
- ③に不要な詳細解説・音声が追加されない。
- Narrator／Dialogue／速度／Chunkが正式仕様に一致する。
- ASR・音声品質・Style・Assembly GateがPASSする。
- retry／fallback／regeneration／resumeと整合する。
- 本文・表示・音声・学習内容の一致を確認する。
- 正式Production経路でのruntime evidenceを取得する。
- 必須Regression／Validator／Integration TestがPASSする。
- Fable独立受入を実施する。
- CURRENT_SPEC／DECISION_LOG／OPEN_ITEMS／Gitを適切に更新する。

制作工程の完了と、ユーザーによる最終試聴承認は区別すること。

## 7. QCD・作業進行

優先順位：品質 ＞ Delivery ＞ 量産単価 ≫ 開発費用。

- 本文の再生成は行わない。
- 選定フォーム準備と独立した音声制作準備を並列化する。
- 既存の有効なコード・設定・固定資産を再利用する。
- 今回指定した音声再制作以外の不要な再生成を避ける。
- 量産単価70円／記事セットの目標を意識する。
- 開発費1,000円／日（JST）と既存の個別承認枠を管理する。
- 予算内の不具合は既存委任範囲で自律的に解決する。
- 品質・安全・仕様・承認境界を守る。
- 未承認の新方式や品質基準変更を行わない。

既存の音声を全面的に作り直すため、制作費用は通常より増える可能性がある。既存資産を使って不要な費用を抑え、実費と追加費用を明確に報告すること。
