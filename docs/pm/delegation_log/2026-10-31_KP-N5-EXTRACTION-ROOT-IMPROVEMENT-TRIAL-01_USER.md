# Claude Codeへの指示｜N5 Key Phrase候補抽出の根本改善・自律Trial

## 1. 目的

`KP-N5-PHRASE-COVERAGE-AUDIT-01` の調査結果を踏まえ、Key Phrase候補抽出の構造的な取りこぼしを解決してください。

**最低達成条件は、`put away` と `in the way` の両方を、本文の意味に合った学習候補として適切に抽出できる方式を確立することです。**

単に難易度条件を緩和するだけでは不十分です。特に `put away` は条件5を外しても抽出できていないため、候補抽出そのものの原因究明が必要です。

ユーザーに未解決の対策案を選ばせるのではなく、AI側で原因究明・対策立案・Trial検証・改善を自律的に進め、実証済みの方式を提示してください。

優先順位は **品質（Q）＞速度（D）＞量産単価（C）≫開発費用** です。

## 2. 原因究明

まず、既存の調査記録・承認済み仕様・Prompt・Production経路・過去Trialを確認してください。

重点調査事項：

1. `put away` が9回の抽出試行で一度も拾われなかった原因。
2. 条件5を外しても `put away` と `leave out` が抽出されない原因。
3. `in the way` が補完枠では拾えるものの、安定して抽出されない原因。
4. 句動詞・固定表現・分離形・本文中の繰り返し・文脈などが抽出に与える影響。
5. 抽出段階とN5選定上限7件のそれぞれで生じる取りこぼし。

**抽出されない問題と、抽出後に選定から落ちる問題を明確に分離してください。**

原因を推測だけで確定せず、Prompt・入力・中間出力・実行結果で裏づけてください。

## 3. 対策立案・Trial

単一のPrompt変更に決め打ちせず、複数の有効なアプローチを比較してください。

検討対象には以下を含めます。

- 既存抽出Promptの改善
- 句動詞・固定表現を明示的に探索する方法
- 分離形や文脈から表現を発見する方法
- 抽出工程を分ける方法
- 候補抽出と難易度・学習価値判定の役割分離
- 既存の候補上限7件・選定順との整合

これらは検討候補であり、実装方法を固定するものではありません。Claude自身でより有効な方法があれば採用候補として比較してください。

Trialでは、最低限以下を確認します。

1. `put away` と `in the way` の両方を、偶然の単発成功ではなく、十分な再現性をもって抽出できること。
2. 本文中の意味を正しく認識できること。
3. 最終候補まで残せること。抽出成功だけをもって改善成功としないこと。
4. `leave out`、`in sight` などにも改善効果があるか。
5. 不要な易しい表現、意味の不適切な表現、本文に存在しない表現が増えないか。
6. 他の有用なKey Phraseが押し出されるなど、既存品質への悪影響がないか。
7. Family X/Y/Z、Standard/Advancedの共通仕様・既存Gateへの影響。
8. 推定量産単価、処理時間、retryを含む運用負荷。

特に**特定の2表現だけを狙ったハードコードや、その記事だけに通用するPrompt調整は不可**です。一般化できる抽出方式を目指してください。

## 4. 自律改善ループ

原因究明 → 複数案設計 → Trial比較 → 副作用検証 → 改善を自律的に繰り返してください。

- 1回のTrialで可能な限り多くの有効な比較・知見を得る。
- 独立した調査・検証は並列化する。
- 失敗した場合は原因を分析し、Promptだけでなく工程構成も見直す。
- 同じ方向の効果の薄いTrialを反復しない。
- 承認済み品質を満たした時点でTrialを終了し、過剰な磨き込みは行わない。
- Trial成功後も、ユーザー承認前にProductionへ配線しない。

既存のN5本体は正常と報告されています。変更の必要性が実証されない限り、その意味判定・一般化処理は維持してください。
