# Claude Codeへの指示｜日本語ASR「月のしわ」問題の根本解決・PM管理不備の原因究明

## 1. 目的・ユーザー決定

Family X『月は少しずつ縮んでいる？』の日本語タイトル「月のしわ、8,900本超！その奥に潜む『岩の上着』の秘密」において、正常な音声がASRで繰り返しNGとなる問題を根本解決してください。

今回は単なる原因調査ではありません。

**原因究明 → 対策設計 → Trial → 評価 → 改善の自己ループを実施し、正しい音声を正しくPASSし、誤った音声をNGにできるASR仕様を確立することが目的です。**

同時に、なぜ過去のPM管理で、この問題を解決しないまま関連対策の完了を認めたのか、Claude・Fable双方の管理責任を調査してください。

### 今回のユーザー承認範囲

- 根本原因の調査、改善案の設計、必要なTrial、再検証を承認。
- 既存の検証データ・保存音声・ASR記録を再利用してよい。
- 既承認の開発予算とSTOP条件を守り、技術的問題は自律的に解決する。
- v2／B-light β／P-1は、現時点では正式採用保留。
- **今回のTrial成功はProduction正式採用を意味しない。**

新たな仕様のProduction採用は、ユーザーの明示的な承認を必要とします。

## 3. 課題A｜PM管理不備の原因究明

## 4. 課題B｜日本語ASRの根本改善

### 4-1. 既存方式の正確な再評価

以下を同じ評価条件で比較してください。

- 現行Production判定
- v2読み規則
- B-light β
- P-1（助詞免除）
- 必要に応じて、既存方式の合理的な組み合わせや別アプローチ

過去のTrial結果を再利用し、再実行が必要な部分だけ追加検証してください。

特に、v2・β・P-1の定義や重複関係を明確にし、同じ機能を別方式として二重評価しないこと。

### 4-2. 正常音声のPASS

Human OKの6音声について、それぞれ以下を示してください。

- OpenAIとAzureの実際の書き起こし
- 判定結果とNG理由
- 改善方式ごとの判定結果
- PASS／NGを決めた具体的な条件
- 最終Gateまで通した結果

**PrimaryだけPASSしても、最終Production判定がNGなら解決とはみなしません。**

### 4-3. 誤PASS防止

以下のような実際の誤りを検出できることを確認してください。

- 「月のしわ」と異なる発音
- 「8,900」と異なる数値
- 助数詞の間違い
- 単語・文節の脱落
- 本文の意味を変える読み違い
- 同音異表記の救済に便乗する別の誤り

既存の負例・過去Trialの結果も使用し、従来検出できていたNGを新方式が誤PASSにしないことを確認してください。

正常音声6本のPASSだけを達成するために、安全基準を緩和してはなりません。

### 4-4. 一般化と対象範囲

「月のしわ」という特定タイトルだけを通す例外ルールは禁止します。

同種の助詞、同音異表記、数詞・桁区切り、ASRの表記ゆれに対して、汎用的に成立する方式を検討してください。

Family X/Y/ZのStandard日本語音声について、タイトル・Preview・Comment・KP日本語意味などの適用範囲を確認してください。

Advancedに日本語音声が存在しないなどの仕様上の除外は明確にしてください。

既存のF1+F2・E3・E4および承認済みの安全条件を維持し、改善案との干渉も評価してください。

承認範囲内で解決困難な場合は、未解決理由、代替案、QCD影響を提示してください。

## 6. 合格条件・Status

今回の改善Trialの合格条件は以下とします。

1. Human OKの6音声すべてを最終判定でPASSできる。
2. 既知の実誤読・負例を誤PASSしない。
3. 「月のしわ」固有の例外ではない。
4. X/Y/Zの対象範囲と既存仕様への影響を評価済み。
5. retry／fallback／resume／再判定との整合を確認済み。
6. 実行費用と量産単価への影響を提示済み。

音声の正否を機械的に確定できない場合は、その限界を明示し、必要なHuman Review条件を提示してください。単なる警告付きPASSを無条件のPASSと同一視しないこと。

**上記を満たした場合、改善仕様のStatusはVALIDATEDとしてください。**

未達なら、達成した条件と残る問題を区別し、未解決のままVALIDATEDとしないでください。

Productionコード・正式判定基準への新仕様配線は禁止です。正式採用はユーザー判断後に行います。

なお、既に承認済みのR3/R4不具合是正は、本Trialの新仕様採用とは切り分けて進め、互いの検証結果を混同しないでください。

## 7. QCD

優先順位は次のとおりです。

**品質（Q）＞完成速度（D）＞量産単価（C）≫開発費**

量産単価の全体目標は70円／記事セットです。

- 誤PASS防止を犠牲にした見かけ上のPASS率向上は禁止。
- 安全性を確保したうえで、正常音声の不要なNG・再生成を削減。
- 既存データ再利用、API呼出削減、試行回数削減を検討。
- 開発費は既存の承認枠と原則1,000円／日（JST）の範囲で管理。
- 予算超過や新たな承認範囲が必要になった場合はSTOPして報告。
