# Claude Codeへの指示｜Cドライブ容量監視・自動整理の恒久対策

## 1. 目的・ユーザー承認

`DISK-SPACE-RECOVERY-01` の完了報告を受領しました。

Cドライブ空き容量は最大73.9GBまで回復しており、今回の整理は完了として受け入れます。

今後、同様のディスク容量不足で開発作業が停止することを防ぐため、**空き容量10GB未満をトリガーとする自動整理機構**を導入してください。

これはユーザー承認済みの運用方針です。安全条件を満たす対象について、毎回ユーザー承認を求める必要はありません。

## 2. 容量監視・自動処理

以下を基本仕様とします。

- **20GB未満：予防警戒。** 不要ログの増加や容量消費の原因を確認し、安全な整理を先行実施してよい。
- **10GB未満：自動整理を必ず実行。** 承認済みの安全な削除対象を整理し、容量を回復する。
- **回復目標：原則20GB以上。** 可能なら10%以上の空き容量を確保する。
- 10GB以上に回復できない場合は、原因を調査し、追加対応の必要性を報告する。

Claude Codeの通常作業開始時、長時間処理の開始前、および必要な定期監視で容量を確認してください。

Claude Codeが起動していない時間帯も自動監視する必要がある場合は、Windowsのタスクスケジューラ等を検討してください。ただし、常駐処理や過剰な監視負荷は避けてください。

**容量チェックだけで終わらず、条件に達したら安全な整理まで自動実行すること。**

## 3. 自動削除してよい対象

今回の実績を参考に、以下を候補とします。

1. 終了済みClaude Code taskの一時出力ログ
2. 再取得可能なpip cache等の一時キャッシュ
3. Git上で完全に保存・push済み、差分なし、現在未使用と確認できる作業用worktree

ただし、削除前に必ず以下を確認してください。

- プロセス・Workerが現在使用していない。
- 未commit・未pushの成果物が存在しない。
- Production成果物・SSOT・必要なTrial証拠を含まない。
- 削除対象が所定の安全な場所・種類に一致する。
- 削除により実行中タスクを破壊しない。

Git worktreeは通常のGit管理コマンドで安全に除去してください。強制削除は禁止します。

**対象が安全だと証明できない場合は削除しないこと。**

## 4. 自動削除の禁止対象

以下は容量不足であっても自動削除禁止です。

- Production成果物、正式記事・音声・公開ページ
- CURRENT_SPEC、DECISION_LOG、OPEN_ITEMS等のSSOT
- 未commit・未pushのファイルや作業中のworktree
- 必要なTrial成果・検証証拠
- OS管理ファイル（pagefile、hiberfil等）
- 安全性が確認できないファイル

これらの削除が必要な場合は、理由と影響を示してユーザー判断を求めてください。

## 5. 再発防止

今回の原因である、対話型Pythonの異常なログ増殖に対して、既存の再発防止策を維持してください。

- backgroundでの対話型Python起動禁止
- Worker開始前の容量確認
- 異常増殖ログの早期検知
- 不要ログの安全な回収
- 整理前後の空き容量と削除対象の記録

容量不足を検知してから整理するだけでなく、異常な容量消費そのものを早期に止める仕組みも検討してください。

## 6. 運用・QCD

- 承認済み対象の自動整理は、ユーザーへの都度承認なしで実施する。
- 通常の軽微な整理について逐次報告は不要。
- 重要な削除・回復不能・作業停止リスクは速やかに報告する。
- 既存の進行中タスクを不要に停止しない。
- 自動整理処理によるPC負荷や開発時間への影響を最小限にする。
- 必要十分な仕組みを構築し、過剰な監視や複雑な管理システムにしない。

## 7. 完了条件

以下を確認し、Fableによる独立受入を実施してください。

1. 10GB未満を模擬した検証で、自動整理が正しく発動する。
2. 安全な削除対象のみが処理される。
3. 未保存成果物・Productionデータが保護される。
4. 整理後の容量が再計測される。
5. 容量回復できない場合の警告が機能する。
6. Windows環境で実際の監視・整理経路が有効になっている。
7. SSOT・Gitに運用仕様と実装証拠を記録する。

**スクリプトを作っただけでは完了としません。通常のClaude開発環境で、容量監視から自動整理まで動作可能な状態を確認してください。**

必要なWindows権限が不足している場合は、既存の承認済み手段で解決を試み、それでも実行できない場合のみユーザーに報告してください。

最終報告は、実装状況・実際の起動条件・安全性・テスト結果・残課題を簡潔にまとめてください。
