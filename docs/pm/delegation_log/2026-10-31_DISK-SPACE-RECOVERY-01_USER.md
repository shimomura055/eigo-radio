# Claude Codeへの指示｜Cドライブ容量不足の緊急調査・不要ファイル削除・再発防止

## 1. 目的・優先度

Cドライブの空き容量が約1.4GBまで減少している問題について、優先度を上げて対応してください。

**目的は、eigo-radioのProduction環境・既存成果物・進行中タスクを保護しながら、不要ファイルを削除して十分な空き容量を回復し、容量不足の再発を防ぐことです。**

調査報告だけで作業を終了せず、承認範囲内で削除・整理・検証まで自律的に進めてください。

- 優先度：高（制作環境の安定性に関わる）
- Status：対応承認済み・実施前
- 目標：安全な容量回復と原因解消
- 優先順位：品質・データ保全 ＞ 復旧速度 ＞ 費用
- 追加API費用：原則0円

他の進行中タスクは、不合理に全面停止させないでください。ただし、ディスク容量不足による書き込み失敗やデータ破損が懸念される処理は、安全を確保するまで停止・調整してください。

## 2. Phase 1｜容量使用状況の調査

まず、Cドライブ全体の容量と使用状況を確認してください。

調査項目：

1. 総容量・使用容量・空き容量
2. 容量を多く消費しているフォルダ・ファイル
3. 最近急増したファイル・フォルダ
4. eigo-radio関連のTrial・Production出力
5. Claude Codeや他の開発ツールが生成したキャッシュ・一時ファイル
6. Python、Node.js、その他の開発環境のキャッシュ
7. Windowsの一時ファイル・ログ
8. 重複ファイルや不要になった中間生成物

特に、直近のTrial・Production実行で容量が急増していないか確認してください。

単にファイルサイズが大きいという理由だけで不要と判定しないこと。

## 3. Phase 2｜不要ファイルの安全な削除

調査結果に基づき、ファイルを以下の3種類に分類してください。

### A. 自律削除可能

用途・所有者・再生成可能性を確認し、削除してもProduction・監査・再開・他タスクに影響しないと確実に判断できるもの。

例：

- 明らかに不要な一時ファイル
- 不要になったツールキャッシュ
- 参照されていない一時的なビルド生成物
- 終了済み処理の不要な作業残骸

これらは承認範囲内で自律的に削除して構いません。

ただし、共有キャッシュや実行中プロセスが使用しているファイルは、利用状況を確認してください。

### B. 個別判断が必要

以下は、不要と断定できない限り削除しないでください。

- 過去Trialの音声・生成成果物
- Production実行記録
- 検証用fixture
- バックアップ
- Git管理外の成果物
- 監査証拠・runtime evidence
- 再生成に費用がかかるデータ
- 他タスクが利用する可能性のあるファイル

削除候補、容量、削除リスク、代替保管方法を整理して報告してください。

### C. 削除禁止

以下は明示的な追加承認なしに削除しないこと。

- Production成果物・正式音声Store
- CURRENT_SPEC／DECISION_LOG／OPEN_ITEMS
- Git未commitの作業成果
- 進行中タスクの作業ファイル
- retry／resume／再生成に必要な記録
- 復旧に必要なバックアップ
- 他タスク・他プロセスが使用中のファイル
- OS・アプリケーションの正常動作に必要なファイル
- 用途不明で重要性を否定できないファイル

Windowsのシステムファイル、ユーザーの個人ファイル、他アプリのデータについても、推測による削除は禁止します。

**削除対象の範囲を最小限に限定し、OSの保護機構やアクセス権限を回避して削除しないでください。**

## 4. Phase 3｜容量回復・動作検証

安全に削除できるファイルの整理後、次を確認してください。

1. 削除前後の空き容量
2. 実際に回復した容量
3. eigo-radioのGit状態
4. Production・Trialの主要ファイルの存在
5. 進行中タスクへの影響
6. 通常の制作・再開処理が継続可能か
7. 同じ原因で急速に容量が減少しないか

空き容量は、可能であれば**最低20GB程度、またはドライブ総容量の10%以上**を目安に確保してください。

ただし、これは容量確保の目安であり、重要データを削除してまで達成する品質基準ではありません。

安全に確保できる容量がこれより少なくても、無理な削除を行わず、結果と残るリスクを報告してください。

## 5. Phase 4｜再発防止

容量不足の主因が判明した場合は、同じ問題が再発しないよう対応してください。

検討対象：

- 不要な一時ファイルの後片付け
- 作業用ファイルの保存先
- 重複した中間生成物の抑制
- 不要なキャッシュの蓄積防止
- ディスク残容量の確認
- 大量データを生成する工程の終了時処理

既存のファイル保存仕様、音声Store、Production成果物の保持期間などは、ユーザー承認なしに変更しないでください。

再発防止策そのものが、過剰な検査・待機・処理時間を生まないようにしてください。

## 6. 並行作業と安全条件

現在、別タスクとして以下が進行しています。

- 日本語訳品質の調査
- N5 Key Phrase候補抽出の調査
- Phrase・Word出現回数表示

これらの作業ファイルを削除・移動しないこと。

また、以前に作業ツリーの出力記録が旧版へ戻る事故が発生しているため、今回は特に注意してください。

- 作業ツリー全体の一括削除・一括初期化は禁止
- Git clean/resetなどによる広範囲のデータ消去は禁止
- 他タスクの未commit成果物を保護
- 削除前に対象と依存関係を確認
- 削除操作は対象を明示して限定実行
- 容量回復のために別の場所へ大量コピーし、さらに容量を圧迫しないこと

安全性を確認できないファイルについては、削除を保留してください。

## 7. STOP条件

次の場合のみ、ユーザー判断を求めてください。

- 安全に削除できるファイルだけでは必要な容量を確保できない
- Production成果物・監査記録等の削除が必要
- データ移動・保存先変更など重要な運用仕様変更が必要
- OSや他アプリの重要なデータに影響する
- データ破損や重大な不整合が発見された
- 承認済みの作業範囲・費用上限を超える

その他の軽微な技術問題は、承認範囲内で自律的に解決してください。

## 8. 完了報告

以下の順に簡潔に報告してください。

1. **Cドライブの空き容量：対応前 → 対応後**
2. 容量不足の主な原因
3. 削除・整理したファイルの種類と削減容量
4. Production・Git・進行中タスクへの影響有無
5. 再発防止策
6. 削除せず残した大容量ファイルと理由
7. 残存リスク・必要なユーザー判断（ある場合のみ）

削除対象の詳細パス・操作記録は内部証拠として保持し、ユーザーへの報告は要点中心にしてください。

Fableによる独立確認も実施してください。

---

## 最重要事項

**今回の指示は、調査だけでなく、安全な不要ファイルの削除と容量回復まで承認しています。**

一方、Production・監査・復旧・進行中タスクに必要なファイルの削除は承認していません。

品質とデータ保全を最優先に、可能な範囲で速やかに容量を回復してください。
