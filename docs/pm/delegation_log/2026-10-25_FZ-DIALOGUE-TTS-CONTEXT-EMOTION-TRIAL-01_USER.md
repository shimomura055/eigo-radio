# Claude Codeへの指示
## Family Z セリフTTS 文脈・感情表現 比較Trial

**管理ID：FZ-DIALOGUE-TTS-CONTEXT-EMOTION-TRIAL-01**

### 1. 目的

Family Zのセリフ音声について、現行方式と、前後文脈・感情情報を追加する改善方式を比較し、音声の自然さ・臨場感・感情表現が改善するか検証する。

最上位優先順位は **品質（Q）＞速度（D）＞量産単価（C）** とする。

今回は改善方式の検証のみ。Production採用・実装は対象外。

### 2. Trial対象

- 対象作品：Family Z『賢者の贈り物』
- 対象：代表的なセリフ8〜12件程度
- 異なる感情・演出・会話状況を網羅する
- DellaとJimの両方を含める
- 比較対象は同じ英文・同じVoiceとする

選定するセリフには、可能な範囲で以下を含める。

- 喜び・驚き
- 悲しみ・不安
- ためらい・戸惑い
- ささやき・静かな発言
- 感情が変化する場面
- 相手の発言を受けた返答

機械的な網羅のために不自然な対象を増やさず、作品内で有効な比較ができるセリフを選定する。

### 3. 比較条件

**① 現行方式（Baseline）**

現行ProductionのTTS仕様をそのまま使用する。

- セリフ本文
- 既存Voice
- 既存汎用Style Prompt

既存音声が利用可能なら再利用し、不要なAPI再生成を避ける。

**② 改善方式（Context + Emotion）**

①と同一のセリフ本文・Voice・TTSモデル・生成設定を維持し、TTSへのStyle情報に以下を追加する。

- 話者の感情・心理状態
- 場面の状況
- 直前・直後の会話（原則1〜2セリフ）
- 地の文に記載された演出情報
- 相手の発言に対する反応

重要な条件：

1. 文脈・感情情報は、原文と場面から妥当に導ける範囲に限る。
2. 原作にない感情や演技を過剰に創作しない。
3. セリフ本文の英文は変更しない。
4. 読み上げ対象は当該セリフのみ。文脈情報や演出指示を発話させない。
5. 朗読として自然な感情表現を目指し、大げさな演劇的表現を求めない。
6. 現行方式と改善方式の違いは、原則として文脈・感情情報の追加に限定する。

感情・文脈情報の作成方法はClaude/FableがQCDを踏まえて設計する。既存の文章・構造化データを最大限活用し、不要なLLM呼び出しを避ける。

### 4. Trial実施方法

**Step 1：既存仕様・過去調査の確認**

以下を確認する。

- CURRENT_SPEC
- 先行調査 FZ-DIALOGUE-TTS-CONTEXT-EMOTION-INVESTIGATION-01
- EVIDENCE_01
- OPEN-511
- 現行ProductionのTTS Prompt・Voice設定
- 既存音声・音声再利用仕様

特に、先行調査で指摘された「Dialogue音声の再利用キーにStyle hashが含まれていない問題」に注意する。

②の新しいStyleを指定したにもかかわらず、①の保存済み音声が再利用されることを防ぐ。

ただし、Productionの再利用仕様は今回変更しない。Trial内で確実に区別できる方法を使用する。

**Step 2：対象セリフ選定**

8〜12件程度を選び、各セリフについて以下を記録する。

- 話者
- セリフ英文
- 直前・直後の文脈
- 場面の状況
- 想定する感情・演出
- 選定理由

**Step 3：比較音声生成**

①と②を同一条件で比較する。

- 既存音声が有効なら①は再利用
- ②を新規生成
- 1セリフ＝1 TTS callを維持
- 試聴時の音量条件を統一
- 発話内容・Voice・モデルの差による交絡を避ける
- ②のStyle追加情報が実際のTTSリクエストに渡った証拠を保存

**Step 4：品質検証**

以下を確認する。

- セリフ本文が正確に発話されていること
- 余分な文脈情報を読み上げていないこと
- 不自然な間、過度な演技、発音悪化がないこと
- ASR・既存品質検査との整合
- 元の場面・人物像との整合

問題が発生した場合は承認範囲・予算内で原因を調査する。ただし、別方式への拡張やProduction仕様変更は行わない。

### 5. ユーザー試聴ページ

8〜12件の比較音声を一覧できる試聴ページを作成する。

各セリフについて以下を表示する。

- 日本語での簡単な場面説明
- セリフ英文
- 話者
- ①現行方式の再生
- ②改善方式の再生

**①と②をワンクリックで聞き比べられる構成**とし、音声を探すためにページ移動する必要がないようにする。

可能であれば各セリフ前後の会話も確認できるようにし、文脈との自然さを評価しやすくする。

開発者向けの詳細情報は通常の試聴画面に表示しない。

### 6. 評価基準

| 評価項目 | 判断内容 |
|---|---|
| 感情表現 | 場面・人物の感情が自然に伝わるか |
| 抑揚 | 文脈に適した強弱・イントネーションか |
| 会話の自然さ | 相手の発言を受けた返答として自然か |
| 演出 | ささやき・ためらい等が適切に反映されるか |
| 聞き取りやすさ | 英語教材としての明瞭さを維持しているか |
| 安定性 | 過剰演技・不自然なポーズ・発音悪化がないか |

Fableは①②を独立評価し、改善した点・悪化した点・効果がなかった点を具体的に報告する。

機械的な評価だけで自然さを合格判定せず、最終的な聴き味はユーザー試聴で判断する。

今回のTrial用に新たな必須品質基準や過剰な数値Gateを設定しない。

### 7. 費用・QCD管理

**今回のTrial追加API費用上限：30円。**

- 既存音声・既存データを再利用する。
- 有効な比較結果を得るため、独立作業は並列化する。
- 追加生成が不要なら行わない。
- 30円を超える場合はSTOPし、必要な追加予算と理由を報告する。
- 品質を維持できる範囲で、将来の量産単価への影響も概算する。

30円は今回のTrial固有の上限であり、他案件の予算を流用しない。

### 8. Status・Production変更禁止

本Trialは調査・比較検証である。

到達可能Statusは以下に限定する。

- REJECTED
- VALIDATED
- USER_DECISION_REQUIRED

VALIDATEDでもProduction採用とはしない。

Productionへの正式採用、Promptの正式変更、生成経路の変更はユーザーの別途明示承認が必要。

### 9. 完了報告・受入条件

以下を提出する。

1. 試聴ページURL
2. 比較対象セリフ一覧と選定理由
3. ①②の具体的なStyle Prompt・文脈情報
4. Fableによる比較評価と具体的な改善・悪化事例
5. 発話正確性・生成条件・再利用分離の確認結果
6. 実費と将来の量産単価への影響
7. Trial StatusとProduction採用に向けた判断事項
8. OPEN_ITEMS・DECISION_LOG等の必要な更新、Git commit/push結果

**ユーザーが実際に聴き比べ、②の改善効果を判断できる状態を今回の完成条件とする。**

試聴ページ公開とFable評価まで進めたら報告する。ユーザー承認前にProduction採用・実装へ移行しない。

### 10. STOP条件

以下の場合はSTOP・報告する。

- API費用30円超過が必要
- 承認済みProduction仕様の変更が必要
- セリフ本文・Voice割当の変更が不可避
- 有効な比較が成立しない重大な問題
- 安全・品質上の重大な問題
- Trial範囲を超える新方式の採用が必要

既存仕様・予算内で修正できる軽微な問題は自律的に解決する。

最終的に、**現行方式①に対して、改善方式②がFamily Zの物語品質をどの程度向上させるか**を、ユーザーが試聴で判断できる結果を提出してください。
