# 指示｜Key Phrase意味・説明品質の根本改善継続とPM判断是正

## 1. 結論・ユーザー決定

**Key Phraseの日本語意味・Advanced英語説明の品質問題は未解決。改善を継続すること。**

A-1の正式採用は維持する。ただしA-1単独ではユーザーの要求品質を満たしていない。

A-3 v3については、検証結果からProduction採用を推奨しない。一方、**A-3の失敗を理由に、改善タスク自体を終了することは禁止する。**

ユーザーは、期待する品質を実現するまで、原因究明・設計・検証を続けるよう指示している。

## 2. 未解決の品質問題

対象：Family X/Z共通のKey Phrase品質。

代表例：`draw that line`

### Standard

現行：
- Key Phrase：`draw that line`
- 日本語意味：「その線を引く」

A-1適用後：
- Key Phrase：`draw a line`に改善。
- 日本語意味：「一線を引く」の成功例がある一方、「線を引く」「境界線を引く」も残る。

**必要な改善：慣用表現の中心義を捉え、適切な日本語意味を安定して生成すること。**

### Advanced

現行：
- `to decide where the limit is between what is acceptable and what is not`

A-1適用後にも：
- `to set a clear limit on what is acceptable`
- `to set a limit or make a clear distinction`

などが残る。

**必要な改善：本文での意味を正しく踏まえつつ、記事固有の条件に過度に限定されない、汎用的で正確な中心義を説明すること。**

例：
`to establish a clear boundary or limit`

この表現は品質目標の例示であり、文字列の固定出力を求めるものではない。

## 3. 根本原因の再調査

今回のA-3 v3は、記事固有条件を減らす一方で、本文の意味から離れる副作用が出た。

この結果を踏まえ、単にPromptの表現を再調整するのではなく、以下を確認すること。

1. Key Phraseの見出し形・本文での意味・汎用的中心義が、各工程でどのように扱われているか。
2. Standardの日本語意味が逐語訳に戻る原因。
3. Advancedの説明が記事固有の狭い意味、または本文から離れた広すぎる意味になる原因。
4. 現行Prompt、入出力情報、Validator、retry/fallbackのどこに原因があるか。
5. 既存の承認済み仕様・過去Trialを活用して、最も簡潔かつ安定した改善を実現できないか。

**特定のPrompt案に固執せず、問題の本質から改善手段を再設計すること。**

## 4. 改善・検証方針

- A-1の正式採用は維持。
- A-3 v3はそのままProduction採用しない。
- Standard日本語意味とAdvanced英語説明の両方を対象とする。
- Family X/Zの共通仕様として検討。
- 原則として、既存工程の改善を優先し、不要なLLM工程・API費用を増やさない。
- 過去Trialの結果・入力・失敗例を再利用する。
- 独立して進められる調査・設計・検証は並列化する。
- 見込みの低いPrompt変更の反復を避ける。

### 検証で確認すること

1. `draw a line`のStandard日本語意味が適切であること。
2. 同じKPのAdvanced説明が、本文の意味と汎用性を両立すること。
3. 他の慣用句・句動詞・一般表現でも同様の品質を維持すること。
4. 既に正しい説明を壊さないこと。
5. X/Z双方で成立すること。
6. retry/fallbackを含む実際の量産条件で品質を維持できること。

**特定例だけを通す個別対策は不可。**

ユーザー承認済みの品質基準を独断で緩和・変更しない。

## 5. Production Wiringの扱い

A-1は`APPROVED_FOR_PRODUCTION`を維持する。

ただし、ユーザーが要求した意味・説明品質の改善は未完了である。

A-1の先行可能な配線準備は進めてよいが、**未承認の追加改善仕様をProductionへ配線してはならない。**

必要な改善案がVALIDATEDに到達したら、ユーザーに正式採否判断を求める。

採用後はA-1と合わせて、X/Z双方のProduction Wiring、正式runtime evidence、回帰検証、SSOT/Git反映まで進める。

記事B「英国の電車マナー」は、必要な品質改善が正式反映されてから完成版を更新し、ユーザー最終試聴へ提出する。

OPEN-476は引き続き保留とし、本件の名目で無断修正しない。

## 6. PM・Fableの判断プロセス是正

今回、**改善手段A-3の不採用を、品質課題の解決・終了と取り違えたこと**を再発防止対象とする。

今後、Trial Closeoutでは必ず次を区別すること。

- **手段の成否：** Trialで試した仕様・Promptが有効だったか。
- **目的の達成：** ユーザーが求めた品質問題が実際に解消したか。

手段がREJECTEDでも、目的未達なら改善タスクをCloseしない。

効果がない手段の反復は停止する一方、原因やアプローチを見直し、合理的な改善見込みがある限り承認範囲内で自律的に解決を続ける。

品質未達を「現行維持」「仕様不採用」だけで終了処理しない。

この原則を既存PM_GOVERNANCE・FableのTrial Closeout運用と照合し、必要十分な再発防止を組み込むこと。過剰な新Gateや報告工程は設けない。

## 7. STOP条件と報告

既存の予算・承認Scope・安全STOP条件を遵守。

承認済み範囲内で自律的に調査・設計・検証を進める。予算やScopeの拡張、新仕様の正式採用が必要な場合は、根拠とQCD影響を示してユーザー判断を求める。

次回報告は、単なるPrompt比較ではなく以下を中心とする。

1. 日本語意味・英語説明の根本原因。
2. 改善策とその仕組み。
3. 代表例と幅広いKPでの改善・悪化・維持実績。
4. ユーザーの要求品質に到達したか。
5. Family X/ZのProduction反映計画。
6. 残存リスク、QCD影響、必要なユーザー判断。

**最終目的はA-3を採用することではなく、ユーザーが求めたKey Phraseの意味・説明品質を安定して実現すること。**

A-1の採用を維持しながら、この目的が達成されるまで改善を継続すること。
