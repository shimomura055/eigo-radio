## 3. タスクB｜Flap-T救済仕様の設計

### 3.1 問題の背景

今回、米国英語の「latter」に対して、ASRが「ladder」と認識しました。

TTSの実行履歴：

| 回数 | 方式 | ASR結果 |
|---|---|---|
| 1 | 通常（styled） | Ladder |
| 2 | 通常（styled） | Ladder |
| 3 | Fallback（english_lock） | Ladder |
| 4 | Fallback（english_lock） | Ladder |

OpenAI／Azureの2系統、計8判定でNGとなりました。

しかし米国英語では、母音間の/t/と/d/がFlap音として実質的に同じ発音になることがあります。

**音声が正しくてもASRが別綴りを出力するために、再生成を繰り返している可能性があります。**

今回の改善では、このような偽NGを安全に救済することを目指します。

### 3.2 基本方針

既存のASR発音同等性救済機構を優先的に活用し、米国英語のFlap-Tに関する判定を追加する方向で検討してください。

想定する基本フロー：

1. ASRの通常判定で不一致が発生する。
2. 米国英語のFlap-Tによる発音同等性が成立するか確認する。
3. 音韻環境・アクセント・母音・語全体の発音を確認する。
4. 同等と判断できる場合のみ救済する。
5. 同等性が不明・不成立なら従来どおりNGとする。
6. 救済した場合は、その根拠を内部ログに残す。

**単純な文字列のt↔d置換は認めません。**

たとえば、latter/ladderは救済候補ですが、ten/denやtime/dimeを自動救済してはなりません。

また、writer/riderのように米国英語でも母音差が残る場合があるため、子音だけの同等性を根拠にPASSにしないでください。

### 3.3 Voiceの確認

ユーザーから「現在使用しているVoiceは全員米国英語か」という確認があります。

既存ProductionのVoice定義・TTS設定を調査し、Family X／Y／Z、Standard／Advancedについて以下を確認してください。

- 使用Voiceと米国英語設定の実態
- Voice設定上のアクセントと実際の発音の整合
- 英国英語など、Flap-T救済を一律適用できないVoiceの有無
- Voice別の適用可否を判定する方法

未確認のVoiceを米国英語と決めつけないこと。

## 4. Trial設計・検証

### 4.1 検証方針

恣意的に選定した多様なテストケースを用いて、救済できるべきケースと、救済してはならないケースを検証してください。

最低限、次の種類を含めます。

| 分類 | 例 | 検証目的 |
|---|---|---|
| 典型的な救済候補 | latter / ladder | 基本的な同音救済 |
| 別の救済候補 | metal / medal | 特定単語への過適合防止 |
| 条件付き候補 | writer / rider | 母音差の取り扱い |
| 条件付き候補 | betting / bedding | 母音・周辺音の影響 |
| 非対象 | ten / den | 誤救済防止 |
| 非対象 | time / dime | 誤救済防止 |
| 境界条件 | アクセント・母音・前後の音が異なる語 | 適用境界の確認 |
| 実データ | 過去のASR NG音声 | 実運用での有効性 |

上記は例示です。検証対象はこれだけに限定せず、既存の発音辞書・実際のNG記録から追加してください。

特に、救済を容易にPASSさせるテストだけでなく、**誤った救済が起こり得る厳しい反例**を積極的に含めてください。

### 4.2 Trialで比較する観点

- 正しく救済できた件数
- 本来NGのケースを誤ってPASSにした件数
- 救済できなかった正しい発音のケース
- 既存のASR判定・発音同等性救済との整合性
- TTS再生成・Fallback・Human Reviewの削減見込み
- 実行費用および量産単価への影響

既存音声、ASR記録、発音辞書、テストデータを最大限再利用してください。

必要な場合は、比較条件を変えた複数方式をTrialし、品質・実装の単純さ・速度・費用を総合評価してください。

初回方式で期待する品質を得られない場合は、原因を分析し、必要に応じて方式を見直して自律的に再Trialしてください。見込みのない同一方式の反復は避けます。

### 4.3 受入条件

Trialの合格条件は以下です。

1. 典型的なFlap-T同音ケースを適切に救済できる。
2. 単純なt/d置換による誤救済が起こらない。
3. 音韻環境や母音差による不一致を無条件にPASSさせない。
4. 既存のASR Gate・同音救済・retry・fallbackとの整合が取れる。
5. 既存の承認済み品質基準を引き下げない。
6. Family・Voice・レベルごとの適用境界が明確である。
7. 実運用における再生成削減効果と量産単価への影響を評価できる。

既存の音声品質検査を広く緩和するのではなく、発音同等性を合理的に説明できるケースだけを救済すること。

## 5. Production採用の境界

今回の承認範囲は、**仕様設計とTrial検証まで**です。

- 既存Productionコード・CURRENT_SPEC・過去Trialを調査すること：承認済み
- Trial専用実装・比較・検証：承認済み
- Trial結果に基づく改善と再検証：承認済み範囲内で自律実施
- ASR救済の新仕様を正式Productionへ採用・配線すること：**未承認**

Trial成功時は `VALIDATED` として報告してください。

正式Production採用は、結果を見てユーザーが判断します。Trial成功をもって自動的に `APPROVED_FOR_PRODUCTION` や `PRODUCTION_WIRED` へ移行しないでください。

将来正式採用する場合の対象候補はFamily X／Y／Z、Standard／Advancedの共通ASR Gateです。既存の同音救済、retry、fallback、regeneration、resume、検査仕様との整合を考慮してください。
