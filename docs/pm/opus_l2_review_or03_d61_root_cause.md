## 論点1: D61見逃しの原因分析は正しいか → 主因としては誤り
結論: 「Ledger事象名が抽象的すぎた」は主因ではありません。主因・副因は次のとおりです。
主因(【確認】した事実から推定): 選択形式そのものです(NONE付き単一選択)。そこに、HF-009が持つ「暫定の下落」と「最終的な高値復帰」という逆向き2事象の構造が重なっています。
- 同等のラベル(「Brent先物の水準」)で、TRIAL-01 rep3の個別判定ではDECREASED(REVERSED)と判定できています(evidence 01 §E L58)。ラベルが同じで方式だけが違い、結果は2/3検出から0/3に変わりました。
- "oil prices fell" は、上げ幅DECREASEDとは整合し、水準INCREASEDとは矛盾します。どちらの対象を選んでも、文全体(撤回後に下がった=結末として下がった)を正しく表せません。そのためNONEが逃げ道になっています【推測】。NONEでもquoteは記事文を引用しているので、文自体は認識しています【確認】。
- 3 repでラベル表記が違っても(価格/価格水準)3/3 NONEでした【確認】。表記揺れではなく、構造的に決まった結果と見られます。
副因1(【確認】): 上位語の対応付けが弱いです。主語が "oil prices" で "Brent" を含まない文は、faithfulな文でも人工反転文でもNONEが多くなっています(F-01〜04,06、S-01〜05)。これはD61だけの問題ではなく、一群の問題です。ただし、ラベルをさらに具体化するとこの問題は悪化します。逆にTRIAL-01 rep2では汎用ラベル「Brent先物」で検出できていました【確認】。
副因2(【確認】): 前後文(article_context)が投入されていません(`er052_open233_directional_trial_02.py:96`、testsetにフィールドなし)。前の文にBrentが出ていれば対応付けが補われた可能性があります【推測】。
副因3(【確認】): Ledger側のラベルに重複・揺れがあります(rep1は「水準」と「価格」がほぼ同義の2ラベル)。選択肢が割れる原因になります。
gold自体の性質(【推測】、要明示): D61は単純な方向反転ではありません。「暫定の下落を結末として述べ、高値への復帰を落とした」という時間範囲の誤りです。現在のenum(状態の分類)にはこの次元がないため、どの比較方式でもF-09型(暫定の下落を正しく述べた文)とは原理的に区別できません。TRIAL-01でD61の検出とF-09/F-10の誤爆が同時に起きたのは、同じ現象の表と裏です。

## 論点2: 現修正案で改善する見込み
- (a) D61を拾えるか: 低いと見ます。実体名は既に入っています。部分一致を許容すると、"fell" と方向が一致する「上げ幅」(DECREASED=SAME)が選ばれやすく、REVERSEDにはなりません【推測、根拠: F-09/F-10/S-06で、DECREASED系の文は8/8で上げ幅が選ばれた】。仮に偶然「水準」が選ばれても再現性はありません。
- (b) HC-012/A5-0を壊すか: 壊す可能性は低いです。ただし、「機能」を「ヒューマンコンシェルジュ機能」に具体化すると、G-02("the feature in which humans handled the calls")の文字列上の手掛かりが減ります【確認: C-ii表】。意味判断に頼る部分が増えるだけで、利点はありません。
- (c) F-09/F-10/F-19の再発: 再発経路があります。部分一致許容でNONEの閾値を下げると、F-19で「テスト」(STARTEDとENDEDの対でREVERSED)が選ばれる経路が開きます。TRIAL-01で誤爆した実績のある組み合わせです(evidence 02 §B)。
- (d) 具体化しすぎの副作用: あります。"oil prices" / "prices" / "The drop" などの上位語・主語省略の文が、具体的なラベルと対応付かなくなります。S-01〜05型の見逃しが固定されます。
- 部分一致が誤爆を呼ぶ経路: 単一選択と「SAME優先」(`compare_selected` L62)の組み合わせでは、選択が緩くなるほど方向が一致する事象に吸い寄せられます。そのため、誤爆よりも「黙って見逃す」方向に倒れやすいです。逆向き2事象を持つFactでは、反転文が構造的に検出不能になります(S-06は既にこの経路で見逃し)。
## 論点3: 6観点での新たな盲点(修正案を採った場合)
1. 同義表現: 具体化したラベルと言い換え表現(returned to a high level、drop/replaced)のずれが拡大します。別名(alias)・上位語を渡す仕組みがないままです。
2. 主語省略: "The drop was..."(S-14)、"The problem was..."(N-02)は実体名がないため、具体化で対応付けがさらに難しくなります。
3. 比較表現: "did not fall across the board"(S-03)などの否定・比較は、修正案では全く扱われません。テスト数も2〜3件と少なく、評価できない状態です。
4. increase/decrease: 最大の盲点です。逆向き2事象のFactでは、どちらか一方と必ずSAMEになります。部分一致はこれを悪化させます。
5. 一つのFactに複数事象: 単一選択のため、2事象を述べる文(F-05/G-05)でも1つしか比較されません。修正案ではこれも変わりません。
6. 記事側の言い換え: S-01〜05(事象リスト外)のNONEが続きます。NONEが「未言及」として通過扱いになるため、言い換えの反転は全部素通りします。
## 論点4: TRIAL-03へ進む価値 → (B)

修正は次の2点に絞ってください。
- 修正1(主): 時間位置の次元を追加する。Ledger側の各事象に `phase ∈ {INTERIM, FINAL, SINGLE}` を付けます。記事側も、文が「一時的・途中の動き」を述べているか、「結末」を述べているかを `{INTERIM, FINAL, UNSPECIFIED}` で返します。比較は「記事がFINALまたはUNSPECIFIEDならLedgerのFINAL/SINGLE事象と」「記事がINTERIMならLedgerのINTERIM事象と」照合します(Pythonで決定的に処理)。F-09("briefly lost")はINTERIMとして上げ幅と照合されSAME、G-03("fell"、限定語なし)はFINALとして水準と照合されREVERSED、となる見込みです【推測】。

## 論点6: Trial反復の前に直すべき構造上の問題
1. 時間位置の次元がない: 論点4の修正1。最優先です。
2. NONE=通過という失敗時の安全側設計の欠如: fact対応付け済みの文でNONEになるのは異常の兆候です。通過ではなく、フォールバックまたはUNCLEARにすべきです。
3. SAME優先ルール(`compare_selected` L62): 同一対象に複数事象がある場合、一致する方を優先します。修正1を入れた後は、phaseで一意に照合して優先順位ルール自体を不要にすべきです(S-06見逃しの経路)。
4. Ledger側サンプル揺れ: 本番ではfactごとに1回抽出して固定(キャッシュ)し、ラベルを正規化(水準/価格水準/価格を統合)すべきです。多数決より固定+正規化の方が安価で決定的です。2モデル一致(設計doc §8 L321)は未実装のままです。
5. 上位語の扱い: ラベル+上位語(例: 「Brent先物の水準(上位語: 原油価格)」)を記事側に渡すことは有効と見ます。ただし修正1・2と同時に入れると、効果の切り分けができなくなります。
6. 前後文の投入: 本番で使える情報なので有効です【推測】。ただしtestsetに前後文がないため、別Trialに回すのが妥当です。
7. gold・カテゴリ定義: D61型を「方向反転」ではなく「時間範囲誤り(暫定の動きを結末として報じた)」として明示すべきです。gold/KPIの変更はユーザー判断事項なので、ここでは提案に留めます。
