# 人間直送の設計メモ v0(OPEN-233-REVERSAL-DETECT-HUMAN-ROUTE-TRIAL-01 委任_01、2026-10-08)

位置づけ: **設計案(未承認、Trial限定、Production未接続)**。T1の結果(検出器v1がFAIL)を踏まえた記録。実装していない。`APPROVED_FOR_PRODUCTION`なし。

## 1. 設計(Opus診断レビュー3・4項の方針をそのまま記述)
1. 反転型(否定・不在の誤り、主体の取り違え)と構造要素(タイトル・Hook・一行要約の主体)は、**Checkerは検出だけ**。決定論の検出器が印を付けた文は**Rewriteしない**(本文不変)。
2. 印の付いた文は**人間レビューパック**へ直送する(文・該当fact・印の根拠[否定語/肯定fact/主語クラス]を並べる。Checkerの重さ判定=BLOCKING/QUALITY/ACCEPTABLEの格下げ理由は使わない・伏せる)。LLMの重さ判定は制御点にしない(Opus1項: 同じモデルの再判定は読み違いを持ち越す)。
3. 決定論側の入力は(i)否定語+肯定の出来事factの語重なり、(ii)主語クラス不一致、(iii)その両方。語り枠(I/you/we・問いかけ)の文は除外。

## 2. ladder枯渇時の扱い(M4、設計判断として明示)
- Rewrite ladderを使い切ってなおBLOCKINGが残る記事は、**現行どおり既存の許可リストSTOP(`unrewritten_blocking_pass=0`の安全装置)**で止める。この設計は「BLOCKINGを直さないまま出口へ通す新経路」を**作らない**。
- 人間直送は、(a)**Rewriteせず、本文不変のまま人間判定待ちへ振り分ける**ことを意味し、(b)人間が「許容」と判定するまで公開しない(出口はSTOP/保留のまま)。つまりladder枯渇時の人間直送は、既存のSTOP→人間確認と同じ出口であって、新しい自動通過経路ではない。これを設計判断として明示する。
- Productionでこれを有効にするかは別途ユーザー承認(人間のみ)。T1のFAILにより、この設計は現時点でProduction提案の根拠を欠く。

## 3. 人間レビュー率の見積
| 経路 | 規模 | 出典 |
|---|---|---|
| 本設計(検出器v1、全印を直送) | **記事の84.9%(dev 62/73)・88.9%(held-out 24/27)**、記事あたり印の中央値1〜2文(平均1.6〜2.0、p90 3〜5、最大6) | `T1_RESULT.md`、`dev_v1/`・`heldout_final/` |
| 同(v0b) | 記事の97.3%、平均2.4文 | `dev_v0b/` |
| Stage2既存の人間確認パック | 71件(dev 49・held-out 22)、上位10%記事28件(dev3記事+held-out1記事)・重大候補10件 | `STAGE2_RESULT.md` §1-2(5) |
| 上限(記事単位) | 10% | `human_review_priority_v1.md` §3 |
- 本設計の全印直送は、記事ベースで**10%枠の約8〜9倍**、文ベースで1記事あたり約1.6〜2.0件(1記事を読む時間に対して1〜3文確認)。**人間レビュー率の観点でProduction運用不可**。
- 既存の10%パック(Stage2不一致信号の順位付け)との合算は想定していない。印を10%に絞るには、印の優先順位付け(例: neg_subject→neg_absence→subj_class)と上位10%切りが要るが、再現率は元々dev既知NGで1/9(neg1+主体0、located)であり、絞ると更に下がる。

## 4. 10%枠との関係
- 10%枠は「記事単位スコア上位10%のみ人間確認」(`human_review_priority_v1.md`)。本設計の印は**スコアの一信号(T)としては使えるが、直送規則としては使えない**(負荷超過)。T1は「ガード対象型T該当: +1」の根拠を提供するに留まる(重みを0〜+1に保つのが現実的)。
- 結論: 反転型の人間直送は、決定論検出だけでは10%枠に収まらない。10%枠を守る限り、直送対象は「(i)∧(ii)で既知NGに当たる極小集合」か「別信号との併用」に限られ、いずれも再現率は低い。ユーザー判断事項。
