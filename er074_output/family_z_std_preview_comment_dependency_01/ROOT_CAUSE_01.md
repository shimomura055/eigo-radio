# ROOT_CAUSE_01 原因分析(生成前に切り分けの論理を記載、結果を当てはめた)

## 事前に定めた切り分け論理
- EもAと同様に抽象的 -> Family X準拠Prompt構造自体が原因。
- Eが具体的 かつ Bも具体的 -> Comment 2回避が原因。
- Eが具体的 かつ Bは抽象的 -> Comment 1の存在(情報量・回避)が原因。
- Cが具体的になれば -> Comment情報量(参照量)が原因。ただし実Comment 1との重複を併せて評価。
- Dが具体的になれば -> 重複回避の優先順位が原因。

## 結果の要約(Melos、各3 take)
| 条件 | 具体性 | C1重複 | C2重複 |
|---|---|---|---|
| A | 3/3 抽象 | 許容 | 許容 |
| B | 1/3 具体、1/3 半具体、1/3 抽象 | 許容 | 許容〜注意 |
| C | 3/3 具体 | 問題(3/3) | 許容 |
| D | 3/3 抽象 | 許容 | 許容 |
| E | 3/3 具体 | 問題(3/3) | 許容 |

## 仮説別整理
### H1: Comment 2の重複回避が過剰だった
- 支持: B(C2を渡さない)で、A/Dにない「帰り道」「川や襲撃」といった中盤の出来事がB1・B2に出た(2/3)。C2を見せるとその領域を避ける傾向と整合。
- 反証: D(C2は軽微な重複を許容と明記、C2全文は見せたまま)は3/3抽象でAと変わらない。C2回避の緩和だけでは具体化しない。E・Cの具体化は中盤ではなく冒頭前提(人質・結婚式)で起き、これはC2ではなくC1の領域。
- 不確実性: Bは「(生成失敗)」を渡す方式(Family X既存の欠落時埋め値)であり、モデルが「Commentが欠けた」と認識した可能性。n=3で、B3は抽象に戻る。部分的に支持だが主因とは言えない。

### H2: Comment 1の情報量(参照量)が過剰だった
- 支持: Cで各Commentを第1文に縮めると、Previewは実C1の2文目にある前提(人質・結婚式・戻る約束)を述べ、3/3具体的になった。A/Dが抽象なのは、C1が冒頭前提を全部語っているため、それと重複しない具体事実がほとんど残らないことと整合。
- 反証/限界: Cは具体化するが、実際のC1(全文)と3/3重複(問題)。参照量を減らすと見かけの重複回避が弱まり、本当の冗長が生じる。C1縮小は「抽象化の解消」ではなく「冗長の再発」。また事実誤り(姉)・lint違反各1件。
- 不確実性: Std用C1が本文冒頭の前提を全て要約する設計である点が構造要因で、他作品のC1でも同様かは未確認(他作品データなし)。

### H3: Comment 1・2を見せない方が自然なPreviewになる
- 支持: E(完全非参照)は3/3で具体的な出来事から入り、日本語も自然、興味も引く(全条件で最良の読み味)。Family X準拠の枠組み(theme/problem/value)でも具体的な導入は書ける。
- 反証: 3/3でC1と同事実(人質・妹の結婚式・戻る約束・死の命令)を繰り返し、C1重複は「問題」。ユーザー決定「Comment 1の冗長性を重く評価」に照らして、Eはそのままでは不適。Comment 2との重複は軽微(許容)。
- 不確実性: Eは重複回避指示がないので、重複率が高いのは当然とも言える。Previewが前提以外(冒頭の場面等)を選ぶには別の構成指針が要り、それは今回E条件に追加禁止。

### H4: Comment参照と無関係に、Family X準拠Prompt自体が抽象的な出力を誘導している
- 反証(主): Comment関連記述を除去しただけ(新規指示なし)のEが3/3具体的。同一のtheme/problem/value枠、同一の「答え/結論/turning pointを先に言わない」でも具体導入は出る。Prompt枠が抽象化の主因ではない。
- 支持(従): Eでも最後は「信頼に応えられるのか」と信頼に収束する型で、また「冒頭の具体場面の1シーン」ではなく「前提の要約」型に寄る(Advは冒頭場面から入る)。枠が要約型を促す可能性は残る。ただしこれはAdvとPrompt文面自体の違いが交絡しており、今回の条件では切り分けていない。
- 不確実性: 枠の影響は観測できても、除去実験をしていない(新規構成指針の追加はE条件で禁止、今回範囲外)。

## 結論(Melos、n=3の範囲)
1. 抽象化の直接原因は「Previewが、Comment 1と重複しないように、Comment 1が既に語る冒頭前提を避け、残った領域でも具体を出せず抽象主題に退避する」ことである可能性が最も高い(A/Dが抽象、C/Eが具体かつC1重複、の対比)。Comment 2の回避は従たる要因(Bで一部緩和、Dでは緩和せず)。
2. 構造的な矛盾: StdではComment 1が「物語の前提要約」、Previewも「具体的な導入」を担うため、役割が衝突する。重複を避けると抽象、避けないと冗長(C/E)。条件側(参照量・優先順位・非参照)の調整では、「具体的かつC1と非冗長」を3 takeで安定して満たす条件は見つからなかった(B2が近いが1/3)。
3. 事前指定した切り分けの形に当てはめると「Eが具体的 かつ Bは(ほぼ)抽象的 -> Comment 1の存在が原因」に該当(B2は例外的に具体)。Comment 2の回避が過剰というより、Comment 1との役割衝突が主因。
4. D(優先順位変更)はC2に関する軽微許容が効果を出さず(3/3抽象)、有効な対策ではない。
